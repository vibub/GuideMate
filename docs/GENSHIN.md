# 原神攻略视觉与待验收范围

目标游戏为原神；历史验证使用公开攻略参考合集 <https://www.bilibili.com/video/BV1BMgj6MEz4/?p=2> 及开发者本地 AV1 样本。个人录像不随仓库提供，默认 CI 使用合成夹具。以下历史样本结果不能代替当前构建、真实网站或游戏前台验收。

已实现攻略侧的小地图玩家箭头图像识别：本地视频使用同步方向时间轴，在线视频使用实时画面采样。尚未收到对应实机样本，所以实机朝向、相机/角色方向分离、地图位置匹配、视觉战斗判断和自动避让仍未实现。现有战斗辅助依旧来自字幕，不能称为视觉战斗检测。

## 在线视频

本地和在线校准窗口默认“自动识别”。框选完整的青色玩家箭头并松开后，自动判断为原神；也可在“游戏”中手动选择原神或终末地。手动选择不会被后续框选、预览刷新覆盖，切回自动模式可重新判断。没有完整箭头或两种识别器同时匹配时提示手动选择，自动模式未确定游戏时不能保存。识别在本机完成，切换游戏保留当前选区和北向；仅确认保存或完成分析后应用。

在“视觉”页选择“校准在线视频”，从当前画面框选玩家箭头、设置北向，然后“保存并启用”。该操作暂停视频，用户继续播放后每 0.5 秒识别当前画面，无需下载完整攻略或调用 FFmpeg。选区以视频相对位置与大小长期保存，切集、换网址参数、清晰度变化、刷新和重启不会自动改动。分辨率变化只在运行时换算像素位置，不写回新选区；只有用户手动保存新校准才更新，取消不改变原内容。旧版按页面保存的校准优先采用最近观看记录对应的已有选区，无匹配时沿用最后的有效旧条目；原校准表、热键、收藏、进度及登录资料均保留。

网页桥从当前受控视频返回帧和播放时间。跨域媒体无法读取 canvas 时，改为 WebView2 CapturePreviewAsync，并按视频的 object-fit、黑边、iframe 位置和缩放裁剪；支持跨域与嵌套 iframe。原生画面捕获受实际显示尺寸与遮挡影响，小窗过小或箭头未完整显示时明确拒识。较小的在线箭头区域可使用较浅的尾凹阈值，但仍须通过原有轮廓、位置、颜色和几何得分检查；本地离线分析阈值保持原值。

暂停时显示当前时间对应的结果；跳转立即清空，待新帧返回再识别。拒识、无视频、导航、切集、窗口隐藏和最小化均清空旧方向，恢复后重新采样。取帧和识别不重叠，视频或窗口状态变化后丢弃过期结果。在线模式不生成未播放部分的完整时间轴，也不从视频推断用户的实机位置。

隔离本机 HTTP 测试通过同源视频、真实 canvas 跨域拒绝后的原生捕获，以及带边框的跨域和两层嵌套 iframe；真实 B 站 `BV1BMgj6MEz4/?p=2` 的 640×360 画面在 60 秒与 300 秒处成功取帧和识别，并在继续播放后更新方向。这些检查不构成全视频角度精度、所有网站或游戏前台实测。

## 已实现的第一版

1. 读取本地视频尺寸、时长和指定时间的预览帧；校准窗口支持在图像上拖动框选正方形箭头区域、框内拖动移动、四角及四边中点等比缩放，提供放大小地图和原始游戏小地图预设。选区限制在画面内，调整点随预览缩放保持可点击大小；Esc、失焦或鼠标捕获丢失取消本次拖动，关闭校准不替换原资料。
2. OpenCV 的 HSV 掩膜分离高亮青色玩家箭头，使用轮廓、多边形、凸包和尾部凹口判断尖端。尾部允许一个或两个相邻凹口。精确凹口路径拒识后，用较暗的窄青色范围提取完整轮廓，对照不同宽度、尾部形状和每 5 度旋转的数学形状模板；需要相似度至少 0.78、与相隔 40 度以上的候选至少相差 0.02，仍保留面积、中心位置、边界及真实凹口检查。凹口还必须位于候选方向后方、接近中轴，避免把翼角当尖端。过小、触边、缺少凹口、位置偏离、复杂自交或角度存在歧义时拒识。模板仅保存数学图形，不改变用户选区或北向校准。
3. FFmpeg 在本机以每秒 2 帧解码选区，输出每 0.5 秒的角度或未识别记录。分析支持取消；取消或解码失败不会替换已有时间轴，子进程会结束。
4. 时间轴按视频路径、大小和修改时间绑定，存于数据目录 `vision` 子目录。重新打开同一文件自动读取缓存，移动或替换文件重新分析。缓存无游戏截图、Cookie、密码或全局按键。
5. 播放、暂停、快进和回退以当前视频时间查找视觉记录。拒识帧明确清空方向，切换视频不沿用旧时间轴。浮窗显示来源为“攻略箭头 · 视觉”。
6. 只有确认北向固定的小地图才能输出八方位；可输入北向相对画面正上方的顺时针角度。旋转小地图只输出画面角度，不能当成绝对地图方位。

此方法不是训练模型或 OCR；几何得分不是识别概率。作者在攻略中放大了左上角小地图并叠加东西南北字，不能把攻略 ROI 直接用于普通实机窗口。预设仅用于初始校准，不保证所有视频或 HUD 尺寸。

## 本地样本验证

- `01.mp4`：347,887,280 字节；1920×1080；约 60 fps；AV1 视频与 AAC 音频；1193.941 秒。
- 全段 2388 个采样点，1826 帧检出箭头，562 帧拒识；检出覆盖率约 76.5%，不等于准确率，也不证明拒识帧的真实状态。
- 完整离线分析耗时 78.92 秒，来自本机一次实际运行，非性能承诺。
- 三张开发帧用于确定阈值；另有 2、8、12、18 分钟处四张独立帧人工近似标注，检查箭头朝向与 180 度反转。样本过少、标注有误差，不能据此声明全视频角度精度。
- 54 项视觉检查通过，包含 36 个合成旋转、无箭头/圆形/三角形/裁切/纯色拒识、真实 AV1 解码、取消和完整缓存。41 项核心检查与 56 项发布版桌面集成检查通过。
- 结果：`artifacts/genshin-analysis/vision-result.json`、`smoke-result.json`。校准窗口的两张 PNG 是 WPF 内容渲染和布局验证，不替代原生桌面截图或真实游戏验证。

## 依赖

OpenCvSharp4 与 Windows Slim runtime 固定为 `4.13.0.20260627`，官方 NuGet 包随构建恢复，发布包带 native DLL。FFmpeg/ffprobe 使用用户已安装的本机程序，本轮未安装系统 SDK，也不上传视频。公开文档：<https://github.com/shimat/opencvsharp>、<https://ffmpeg.org/ffmpeg-all.html>。

## 需要的样本

把有权使用的材料放到 `samples/genshin`，或直接提供本机路径。不要提供账号密码、登录二维码、聊天内容或支付画面；可遮挡 UID，但不要遮挡小地图、玩家标记和需要识别的 HUD。

| 样本 | 内容 | 用途 |
| --- | --- | --- |
| 正常移动 | 同一小段路线的实机录像与对应攻略片段，能对齐时间和位置 | 判断是否能可靠匹配双方位置 |
| 朝向变化 | 原地转角色、单独转镜头、行走转向的画面 | 区分相机角度、角色角度和地图旋转 |
| HUD 状态 | 小地图清晰的普通探索、战斗开始、战斗结束、菜单与加载画面 | 防止把遮挡或加载误当成战斗 |
| 地图场景 | 至少覆盖一段已知区域，含路口或稳定地标 | 建立有依据的地图参考；不从任意画面猜绝对坐标 |
| 显示参数 | 游戏分辨率、Windows 缩放、窗口/无边框模式、小地图旋转设置 | 确定 ROI 和坐标变换 |

建议先提供 1 至 3 分钟对应片段和 20 至 50 张代表帧。这是首个原型的取样建议，不是精度保证。训练集和验收集必须分开；同一张图不能既当模板又作为唯一识别成功证据。

## 后续实机实现顺序

1. 从样本校准小地图、玩家标记及 HUD 区域，明确所需方向究竟是相机还是角色。
2. 用已验证的图像处理库实现局部特征或模板识别，输出置信度，无法判断时不更新方向。
3. 在单个已知区域对齐攻略与实机位置；有地图基准和校准点后才输出坐标，不承诺全提瓦特通用。
4. 用战斗与非战斗样本验证视觉触发，设置防抖和恢复条件，再接入暂停/避让。
5. 在真实原神前台测试热键、覆盖窗口、按键释放、DPI 和性能，确认没有游戏输入或保护机制冲突。

不注入游戏、不读取游戏内存、不自动操作角色，不以降低安全设置或规避保护来解决兼容性。视觉阶段使用屏幕和攻略画面作为输入，是否允许捕获及材料授权由用户确认。

## 验收指标

记录方向角误差、无法识别率、误报率、位置误差、战斗误触发次数、处理延迟和 CPU/GPU 占用。最终阈值应在样本基线后确定；现在没有数据，不填写虚构精度或可靠工期。

真实游戏、独占全屏、管理员权限、多显卡、多显示器及多 DPI 仍需分别实测，不能由本地播放器测试替代。
