# 随引实现文档

版本：1.2；日期：2026-10-07；目标平台：Windows 10/11 x64。

## 1. 目标与证据范围

随引（英文工程名 GuideMate）是边玩游戏、边跟随视频攻略的桌面工具。主要工作流是打开攻略、把视频缩为置顶窗口、在游戏前台用热键控制视频，并在独立浮窗查看同步字幕和方向提示。中文产品名统一用于窗口、托盘、提示和文档；工程、启动入口、互斥量及数据目录仍保留 GuideMate，避免影响已有设置与登录数据。

参考软件为“懒人妈宝 For Python”。本项目自行实现，不复用其品牌、二进制或未知来源的模型。作者公开仓库 master 页面仅列出 README、许可证和 gitignore；更新记录声明 6.0 改用 Python，而 README 仍描述旧版架构。公开说明不能证明具体模型结构或识别准确率。腾讯文档全文未成功读取，原程序未实测。

### 2.2 本版不冒充已实现的能力

已具备字幕方向规则，以及用 OpenCV 识别本地原神攻略中的玩家箭头。后者仅是攻略画面方向，不是实机定位或角色/相机分离，也不是训练模型。缺少对应实机、标注和地图基准时，不能宣称与原软件同等的 AI 朝向、坐标或全场景识别。自动防遮挡仅使用字幕事件和手动窗口设置。

自动采集、自动战斗、自动对话、游戏进程注入和游戏内存读取不属于本版攻略辅助范围。

## 3. 技术选型

客户端采用 C#、.NET 10 LTS、WPF。使用 Microsoft.Web.WebView2 的 WebView2CompositionControl，在 WPF 层处理工具栏、遮罩和透明裁剪，避免普通 HWND 嵌入控件挡住 WPF 元素的 airspace 问题。该控件自 WebView2 SDK 1.0.2957.106 起进入稳定发行版。

使用 Evergreen WebView2 Runtime。此次实际开发环境是用户已安装的 .NET SDK 10.0.401、.NET Runtime 10.0.12、WebView2 Runtime 154.0.4258.53。NuGet 固定 Microsoft.Web.WebView2 1.0.4258.31。WPF 目标框架为 net10.0-windows10.0.17763.0，显式包含 Windows SDK 契约，否则 composition 控件可能在启动时缺少 Microsoft.Windows.SDK.NET。发布采用 win-x64 框架依赖多文件，包内不包含 .NET；运行需要系统已安装 .NET 10 Desktop Runtime x64 和 WebView2 Runtime，无需 SDK。原生 GUI apphost 在执行托管代码前解析运行时，缺失时显示安装提示与官方下载链接，不自动安装，也不访问用户资料。

不采用普通网页作为最终产品：浏览器页面不能独立完成 Windows 全局热键和跨程序鼠标穿透。也不在本版引入服务端或付费模型 API。

## 5. 浏览器与播放器

### 5.1 状态桥

在每个文档创建时注入自有 bridge.js，并在应用接收 WebMessageReceived。消息至少包含类型、播放时间、总时长、暂停状态、倍速、音量、静音、标题和当前可见字幕。

桥接脚本周期性查找当前页面可见的视频；多视频时选择显示面积最大的元素。使用 video.play()、pause()、currentTime、playbackRate、volume、muted 控制播放。play() 的拒绝结果要回传，不吞掉自动播放限制。

应用只接受有限类型的数据消息，不根据网页消息执行任意脚本、打开任意文件或调用系统功能。结构化 JSON 经解析后更新 UI。脚本命令参数经 JSON 序列化，避免把用户字符串拼入 JavaScript。

### 5.2 网页适配

通用控制针对 HTML5 video。分集播放、页面字幕 DOM 和页面聚焦属于站点适配，不能保证所有网站相同。B 站字幕读取当前视频所在播放器的新版 bili-subtitle-x 普通/原语字幕节点，同时兼容旧版 bpx 和 bilibili-player；双语按 DOM 顺序保留，保留显式换行，排除菜单及 AI 标识、重复文本和隐藏/透明节点。优先显示原生 showing 状态的 subtitles/captions 活动轨道，不把 metadata/chapters 当作字幕。沉浸 CSS 隐藏网页字幕层时仍同步当前文字，站点通过 display/opacity 关闭字幕则清空，视频 seeking 时不发送旧字幕。支持用户导入字幕。登录和会员权限由原网站处理，不绕过权限或验证码，不保证能取得网站未提供的字幕。

进入新视频或新集时，桥接自动开启原生 HTML5 中文字幕，或点击当前 B 站播放器主字幕菜单中可用的中文语言项；普通中文优先于中文 AI。仅操作主字幕，不选择副字幕或翻译音轨，不展开网页菜单。等待异步加载最多 120 次状态轮询（正常约 30 秒），无响应的语言项最多点击三次；确认开启后停止干预，保留本集内的手动关闭与语言选择。B 站以页面路径和 p 参数区分集数，清晰度、来源参数和时间锚点变化不重新初始化。网站隐藏的登录受限语言区及禁用条目不操作；沉浸仅隐藏网页控件的 visibility，不妨碍字幕默认开启与同步。

VideoRouter 监听顶层和 CoreWebView2Frame 的创建、嵌套创建、DOM 就绪、消息、导航和销毁。每个来源报告可见视频面积，路由器选取有效面积最大的来源，将命令直接发送到该 Frame.ExecuteScriptAsync；不会通过顶层 JavaScript 越过同源策略。旧状态超过 1.5 秒失效，隐藏框架和已移除的框架不作为有效播放器。

跨域子框架不能读取父级 DOM，因此通过只含随机标识和可见比例的 postMessage 与直接父级协作，确认 iframe 在父页面的可见面积。聚焦时逐级扩展对应 iframe 和视频，退出时移除自有样式。原生控制 API 使跨域 iframe 可路由，但媒体权限、沙箱和网站限制仍可能使特定页面不可控制，必须明确反馈，不保证所有站点。

bridge.js 的分集动作在顶层页面执行，采用 B 站、YouTube 的明确选择器和通用 rel=next/prev 入口。跳过禁用选项，首尾无相邻集时返回不可用。页面地址或实际媒体来源变化时清空上一视频的导入字幕和战斗事件，不沿用旧进度。多视频播放仍默认选择最大可见视频，未提供所有站点的专用播放列表 API。

B 站当前视频选集优先识别 `.video-pod__list .video-pod__item`，按 DOM 顺序及 active/on/playing 等当前项标记选择相邻条目；保留旧 `.multi-page` 和 `.video-episode-card` 适配。新版 multip 分 P 列表不依赖网站点击事件，也不点击任意后代链接，而是用 URL/SearchParams 在当前视频网址设置相邻 p 参数并正常导航。保留其他来源参数、移除旧 t 时间参数，不跨出已识别选集范围。新文档首次报告媒体状态时，若仍处于沉浸则重新 focusOn，保持视频聚焦。其他列表继续已有点击方式。

B 站列表不再按布局高度过滤：列表折叠、响应式隐藏或沉浸聚焦时仍有有效的选集节点，隐藏不应让热键失效。新版页面的每个条目均含 playing-gif（未播放项隐藏该图标），不能仅凭图标存在判定当前集；本实现使用条目的当前类。已找到当前列表时首尾直接返回不可用，不再回退点击无关 rel 链接。YouTube 和通用入口的原可见性策略保持不变。

正式应用内的历史桌面冒烟与在线探针已移除；独立窗口专项 Specs 只验证离线桌面窗口，通过 --isolated 使用独立资料人工核对真实 B 站的选中项、p 参数及视频变化。核心字幕、热键、Chrome 和弹幕模型回归仍独立保留。

### 5.3 本地媒体与样例

应用为内置 assets 建立 guidemate.local 虚拟主机，本地播放器地址是 https://guidemate.local/local.html。media.guidemate.local 不做目录映射：仅 /video 路径由 WebResourceRequested 处理器返回用户刚选中的文件。请求 URL 不携带任意磁盘路径，也不开放所在目录。

读取必须同时满足：顶层文档是内置 local.html、存在用户选择的媒体路径、请求为 GET 或 HEAD。否则返回 403 或 405。文件移动或权限问题返回失败并显示读取错误。CORS 仅允许 https://guidemate.local，选文件不会自动上传；远端页面不能通过该接口获取本地媒体。

MediaResponse 支持完整文件 200、单段字节范围 206、无效范围 416，以及 HEAD。返回正确的 MIME、Content-Length、Content-Range 和 Accept-Ranges，RangeStream 只提供指定范围，以支持浏览器解码和跳转。容器出现在文件选择列表不等于该容器内的所有编解码器都可用；实际解码能力取决于 WebView2 Runtime。

无网络样例采用 FFmpeg 生成的 40 秒 WebM 动态测试视频，通过真实 HTML5 video 解码、播放和跳转，避免用纯计时器伪装视频控制。样例字幕包含东南西北、否定、转向、战斗事件。

## 6. Windows 热键与窗口状态

主窗口置顶由 WindowTopmostMode 三档控制：Never（不置顶）、Immersive（沉浸置顶）、Always（始终置顶）。启动、选项变化和进入/退出沉浸时重新计算 Window.Topmost；最大化不等于沉浸，紧急恢复退出沉浸后按原模式解除或保留置顶，不改写用户选择。侧栏使用三项下拉框，选择立即保存。

沉浸小窗拖动由 WPF Thumb 管理按下、鼠标捕获与结束；DragStarted 将抓取点转为物理屏幕坐标，并保存它相对原生窗口左上角的偏移。拖动期间从 GetCursorPos 读取最新物理鼠标位置，直接减去固定抓取偏移得到目标，不依赖排队的 DragDelta 局部位移，也不累加尚未应用的输入。负坐标与显示缩放沿用屏幕物理坐标；混合 DPI 跨显示器仍需实测。原 DragMove 会发送 WM_SYSCOMMAND/SC_MOVE 并进入 Windows 拖窗循环，贴边时触发 Snap 预览；直接移动窗口避免该入口。Thumb 保持原拖动图标、提示、34×32 尺寸与悬停/拖动状态样式；手动缩放与普通标题栏 DragMove 保留。

拖动使用仅在捕获期间存活的独立 16 ms System.Threading.Timer 触发，以 DispatcherPriority.Send 向 UI 线程提交最多一个回调。计时触发不等待 WPF DispatcherTimer 的消息队列晋级；位移采样与一次 SetWindowPos 在 UI 线程执行，先于排队的 Render/Normal/Input 工作，同步更新两轴并保留 SWP_NOSIZE | SWP_NOZORDER | SWP_NOACTIVATE 与浏览器位置通知。慢回调期间合并计时触发，不堆积历史鼠标坐标，不改变视频采集帧率；它不能抢占已经执行中的长 UI 操作。原生主鼠标键状态考虑左右键交换，避免排队的 WPF 松开事件让窗口继续跟随。松开会读取并应用最后位置；取消捕获、切换模式、最小化、隐藏及关闭会停止计时并作废已提交回调，后续旧回调不能移动恢复后的窗口。

主窗口八方向缩放由四个 6 DIP 边缘 Thumb 和四个 18 DIP 角落 Thumb 处理。WM_NCHITTEST 对窗口内的坐标返回 HTCLIENT，避免原生缩放框截走控件输入；普通标题栏仍显式使用 DragMove。沉浸时 ResizeMode.NoResize 关闭原生缩放框，自定义缩放通过 SetWindowPos 同时更新位置和宽高，保留 SWP_NOZORDER | SWP_NOACTIVATE，不发送 SC_SIZE/SC_MOVE。缩放沿用输入计时合并机制，以起始物理矩形和最新鼠标位置计算，结束保存，取消、导航、隐藏和模式切换丢弃待处理任务。最大化时隐藏手柄；底边细进度线位于缩放边缘上方，仍可跳转。

WindowResizing 对普通窗口自由缩放，对沉浸窗口联合约束宽高最小值和视频比例。角落位移投影到比例直线并固定对角，单边缩放固定对边并让另一轴围绕中心变化；屏幕坐标按有符号值处理。当前比例独立读取所有 state 消息中的视频 width/height，不依赖只处理在线视觉的状态字段。进入沉浸或视频尺寸变化时调整比例；导航、播放器切换和无视频时清理旧比例并取消缩放，尚无尺寸时先采用保存比例或默认 16:9。

ImmersiveBounds 与普通窗口几何独立持久化。进入沉浸保存普通 RestoreBounds 和窗口状态，退出恢复；最小化只保存还原尺寸。旧资料缺少 ImmersiveBounds 时保留原 640×360 默认值。字幕窗口只保存位置和宽度，继续 SizeToContent.Height；拖动及宽度调整结束通过 PlacementChanged 即时保存。SubtitleOpacity 默认 1，加载限制为 0.2–1，设置保存后应用于正在显示的浮窗，取消不更新；其他资料保持原值。

新配置通过可空 TopmostMode 持久化。旧配置未含该字段时，读取原 Topmost 布尔值：true 对应 Always，false 对应 Never；新模式优先于旧值，选择后同步旧布尔字段以兼容既有配置。无效枚举值在设置读取边界回退到旧值。默认保持已有的始终置顶行为，不能借功能升级重置用户设置或浏览器资料。字幕浮窗不跟随主窗三档变化，仍是独立置顶窗口。

### 6.1 默认热键

默认使用组合键降低与游戏冲突：Ctrl+Alt+Space 播放暂停；Ctrl+Alt+Left/Right 后退/快进；Ctrl+Alt+Up/Down 倍速增减；Ctrl+Alt+Shift+V 临时倍速；Ctrl+Alt+PageUp/PageDown 上一集/下一集；Ctrl+Alt+Shift+I 沉浸；Ctrl+Alt+H 隐藏恢复；Ctrl+Alt+P 穿透。固定紧急恢复键优先注册 Ctrl+Alt+F10，失败后尝试 Ctrl+Alt+Shift+F10，不能由普通设置删除。两组均失败时禁用穿透；侧栏和设置显示实际注册的组合。本机实测使用后备组合。

用户可修改普通热键。RegisterHotKey 注册失败必须指出具体冲突；提交新设置时先验证，失败则恢复旧组合。两个普通操作使用同一输入仍被拒绝，但 TemporaryRate 可以与一个普通操作共用；按解析后的组合分组，键盘每组只注册一次，鼠标每组只安装一个分派入口，兼容侧键别名。没有注册成功的热键不得在 UI 标为可用。

键盘组合仍使用 RegisterHotKey；鼠标侧键使用 Raw Input 的 WM_INPUT 作为唯一动作来源，通过 RegisterRawInputDevices 为主窗口注册鼠标与修饰键键盘的 RIDEV_INPUTSINK。后台仍接收输入，不能改用仅在前台程序未处理原始输入时才接收的 RIDEV_EXINPUTSINK。没有设置 NOLEGACY、CAPTUREMOUSE 或 NOHOTKEYS，不更改游戏输入策略。键盘原始输入只维护左右 Ctrl、Alt、Shift 与 Windows 键状态，避免高权限前台使 GetAsyncKeyState 返回零后组合键失配；其他按键、移动、滚轮和普通鼠标点击不进入动作队列。WM_INPUT 按 Win32 x64 的头部与对齐布局读取，并继续交给默认窗口过程清理。消息时间转换为单调时间，避免排队延迟把短按当成长按。

保留 WH_MOUSE_LL，仅拦截未注入、匹配配置的侧键按下及其配对松开，避免浏览器前进/后退；未匹配输入调用 CallNextHookEx。钩子不分派操作，因此与原始输入同时收到同一次按键也不会重复执行；即使其他软件截断钩子链，原始输入动作通道也不依赖自己的钩子回调。配置保存为 Mouse4 / Mouse5（兼容 XButton1 / XButton2），支持单独使用及 Ctrl、Alt、Shift 的精确组合。录制期间暂停普通键盘与侧键动作，保留紧急键。驱动将侧键重映射为键盘时只能按其输出的键盘组合使用；设置页明确提示权限差异：原神或 BetterGI 前台热键无响应时，正常退出并以管理员身份运行原入口，沿用原资料。用户已反馈管理员运行解决了本机前台侧键问题；其他权限、驱动和硬件组合仍需真实检查。

应用动作经 Dispatcher 异步执行，配置更改/暂停递增版本以拒绝已排队的旧动作。原始输入的按下状态与钩子消费状态独立，松开按原按钮匹配，不要求修饰键继续按住；重复按下不重复执行。新配置注册失败时恢复原映射，退出注销热键、钩子及原始输入注册。两种鼠标通道不记录轨迹，普通热键仍保留既有注册与冲突规则。

HotkeyRecorder 是只读录制输入框，使用 PreviewKeyDown 捕获组合，处理 Alt 的 SystemKey 与输入法转换键，固定顺序显示 Ctrl/Alt/Shift；纯修饰键不提交，数字键统一格式，Esc 恢复本次录制前的值。焦点进入时释放普通全局绑定，以免已注册的组合被系统截走；离开或关闭设置恢复绑定，固定紧急恢复键不释放。录制值仅在保存并注册成功后写入配置。

临时倍速不使用低级全局键盘钩子。首次 WM_HOTKEY 或侧键按下创建待判定手势，默认持续 400 ms 才触发临时倍速，门槛可设置 100 至 2000 ms。达到门槛前松开只执行共用的普通操作，没有共用操作则不执行；超过门槛只触发一次倍速，松开恢复且不再补发短按。判断使用独立 HoldGesture，时间来自单调的 Environment.TickCount64；鼠标消息在回调时记下时间，不能用排队后的时间推断短按时长。

按住期间以 30 ms 定时检查组合及 GetForegroundWindow：键盘读取 GetAsyncKeyState 高位，鼠标侧键及修饰键状态来自 Raw Input 的配对消息，不依赖可能因钩子拦截或权限隔离而失真的系统状态。按钮或必需修饰键释放结束手势，前台切换取消而不补发短按。导航、视频来源切换、录制、设置重注册和紧急恢复同样取消；只对已经激活的倍速发恢复事件。原倍速单独保留，临时值不写入收藏、历史或常规倍速。默认临时 2x，可设置 0.5 至 4x；真实原神或受保护/管理员游戏输入仍待验证。

旧配置补入新增动作时保留已有用户组合。新增默认值若与已存的同名格式组合相撞，从未占用的 Ctrl+Alt+Shift+F1 至 F11 中选取备用键，排除紧急恢复 F10；系统级占用仍由实际注册结果报告。设置列表可滚动，错误和保存按钮固定在底部。

### 6.2 状态模型

普通模式显示浏览器、播放工具栏与侧栏。沉浸模式隐藏工具栏和侧栏，保留视频、拖动按钮与底边细进度线，初始 640×360，最小 320×180；普通窗最小 860×500。切换前临时隐藏 composition 控件，布局完成后在 Dispatcher 的 Loaded 优先级恢复显示，解决本机切换小窗时出现的白屏。保留右下角窗口缩放握柄。实际截图验证了样例与 B 站视频的模式切换和小窗缩放，不能仅凭控件尺寸或浏览器 CapturePreview 判断屏幕绘制成功。

`ImmersiveOpacity` 为可空的新设置，旧资料缺失时继承原 `Opacity`，不改普通窗口透明度。设置显示透明百分比 0% 至 80%，保存时转换为不透明度 1 至 0.2；与热键、X 光偏好一起通过既有 SettingsStore 保存。关闭设置不应用草稿。战斗淡化只临时取当前模式不透明度与 0.25 的较小值，结束恢复该模式的原值。紧急恢复退出沉浸并恢复普通窗口可见度，不重置小窗偏好。

`SmallWindow.cs` 的 X 光使用视频专属 WPF Grid 的 OpacityMask，沉浸根背景透明。WebView2CompositionControl 将自身的 OpacityMask 属性暴露为只读，因此在视频父图层施加遮罩；拖动手柄和底边控制是同级元素，不参与柔化。RadialGradientBrush 使用绝对 DIP 坐标，水平/垂直半径相等，Center 与 GradientOrigin 同步移动，避免随窗口宽高拉伸为椭圆。外半径仍使用保存的 XRayRadius；向内羽化宽度为 `min(radius * 0.3, 32)` DIP，内侧完全透明，羽化带以 alpha 0、40、128、215、255 分段渐变到不透明。只改变透明度，不模糊或覆盖视频颜色；复用画刷，仅更新圆心，不逐帧重建遮罩。旧的中央矩形透明孔仍使用根视觉的几何裁剪。

只有启用 X 光、主窗可见且处于非最小化沉浸状态时启用 16.7 ms DispatcherTimer；通过 GetCursorPos 获取真实屏幕位置，再用 PointFromScreen 转入浏览器坐标，不能依赖透明像素触发的 WPF MouseLeave。真实退出窗口区域才撤掉孔，视频边缘、拖动句柄、拖动捕获和进度拖动期间不挖孔。隐藏、最小化、关窗、关闭 X 光或退出沉浸停止计时并清除遮罩。零 alpha 中心不拦截输入，下方游戏可接收输入；羽化带是半透明视频，仍可接收视频输入。游戏自身光标策略不由本程序接管。多显示器混合 DPI 和物理鼠标行为需另行验收。

底边使用独立的 14 DIP 鼠标目标与 3 DIP 轨道/已播前缀，不给视频布局增加高度。进度来自既有路由器 currentTime/duration，夹取到 0 至 1；导航、无视频和未知时长清空。悬停时间显示在底边上方，离开收起；拖动仅预览，释放时通过既有 position 命令跳转一次。失去捕获、切模式、隐藏、最小化或导航取消拖动而不提交过期跳转。隐藏/恢复热键原样保留沉浸状态和网页；紧急恢复入口保持其退出沉浸的原义。

穿透是一种独立状态，不等同于透明；用 WS_EX_TRANSPARENT/WS_EX_NOACTIVATE 和 WPF 分层窗口实现，恢复时移除对应状态。

沉浸模式不沿用网页播放器的隐藏光标策略：视频聚焦 CSS 显式设置 cursor:default，WPF 工作区用 Cursor=Arrow、ForceCursor=true 覆盖浏览器子控件返回的空光标。退出沉浸后解除强制光标，网页样式正常恢复，不设置全应用 Mouse.OverrideCursor。

普通窗口、最大化、网页聚焦和 iframe 也必须保持指针可见。VisibleCursorWebView 继承 composition 控件，在 CursorProperty 的强制回调中只将空值或无效原生句柄转为 Cursors.Arrow，保留正常手型、文本、缩放及其他有效自定义指针。SDK 通过 CursorInteropHelper.Create 包装 Win32 句柄，零句柄产生的新 Cursor 并不等于 Cursors.None；仅比较单例会漏掉真正的隐藏指针。WPF 没有公开句柄读取接口，当前实现缓存读取内部 Handle 属性的反射元数据；使用系统安装的 .NET 10；升级运行时补丁时需重新验证包装指针用例。不修改普通页面或 iframe 的 CSS，不使用全应用光标覆盖，也不依赖鼠标从哪一侧进入。

HTML 原生媒体控件属于视频内部，不能靠隐藏网页 DOM 去掉。聚焦时记住原 video.controls 状态，鼠标移动/点击或按键后保持显示 1.8 秒，无输入时关闭 controls，暂停也自动隐藏；指针按住拖动或媒体 seeking 时延后隐藏。鼠标箭头始终独立保持可见。退出聚焦、视频消失或切换时清除定时器和监听并恢复原 controls；重复 focusOn 不把临时隐藏状态误存为原状态。原来没有原生控件的网站不额外开启 controls。跨域子帧在自身桥接脚本内使用相同控制逻辑，父帧仍只扩展 iframe。

紧急恢复操作必须：显示主窗、关闭穿透、退出沉浸、取消挖孔、恢复正常透明度并激活主窗。热键、托盘和进程退出路径均由一个状态协调入口处理。

挖孔使用 WPF 几何差集裁剪根视觉，保持孔区域 alpha 为零。视频使用 composition 控件，因此不能被普通子 HWND 绕过裁剪；实际 GPU 视频绘制需要截图验证。尺寸与孔大小使用 DIP；窗口位置恢复用 GetWindowRect 和最近显示器的物理像素工作区夹取，再通过 SetWindowPos 移动，避免混用 DIP 与不同 DPI 的屏幕原点。离屏恢复在本机通过回归，多显示器和混合 DPI 的完整矩阵仍待实测。

## 7. 字幕解析与同步

统一模型为 SubtitleCue(StartSeconds, EndSeconds, Text)。SRT 与 VTT 按时间轴行识别；支持逗号或点毫秒，支持 VTT 无小时格式，跳过 NOTE/STYLE/REGION 元信息。正文去除常见标记、解码 HTML 实体并保留换行内容。B 站 JSON 读取 body 数组的 from/to/content，也接受直接数组。

解析完成后按起始时间排序，忽略无有效区间的记录；解析失败向用户给出信息而不清空已加载字幕。当前字幕根据播放时间减去用户延迟计算，处理重叠字幕，不因快进而沿用上一条。

Web 状态以约 250 ms 周期传送，不在 UI 线程执行重识别。用户暂停后字幕冻结，跳转后由新时间重新查找。导入字幕优先于网页字幕；切换视频清空上一视频字幕，样例播放器单独绑定样例字幕。

## 8. 方向与辅助动作

方向解析输出方向标签、角度（北为 0，顺时针）、原始字幕和类别。八方位对应 45 度间隔；左右、前后、上下是相对提示，不能冒充绝对地图朝向。出现“镜头”“视角”时显式标为视角提示。

解析优先匹配明确命令和完整复合方位，避免把“东西”“左右两边”随意解释成路径。检查“不要”“别”“不是”“不用”等近邻否定。多步骤字幕只显示当前文本可直接支持的第一项，不推测执行进度。无方向时显示当前字幕或等待状态，不保持过期箭头。

字幕战斗辅助默认关闭。用户打开后，首次进入含明确战斗词的字幕区间触发一次自动暂停，或短时降低主窗透明度。暂停后不会反复触发相同字幕；导航到新视频重新建立事件集合。此行为在 UI 标注“字幕触发”，不能称为画面识别。

## 9. 浮窗、数据与错误处理

标题栏分别提供最小化和隐藏到托盘按钮：最小化设置 WindowState.Minimized，保留 ShowInTaskbar；隐藏调用 Hide，不将横线图标用于隐藏。StateChanged 记录最后的非最小化状态，暂时隐藏字幕浮窗，不改写浮窗开关。任务栏恢复由状态事件重新显示浮窗；隐藏/恢复热键和托盘/紧急恢复路径会显示并解除最小化，恢复最小化前的正常或最大化状态。隐藏命令是单向且可重复调用，只有隐藏/恢复热键使用切换逻辑。窗口操作不主动发送暂停命令，网站自身的后台播放策略仍由网站决定。

保存非沉浸窗口位置时，正常窗口使用当前尺寸，最小化/最大化使用 RestoreBounds，避免保存最小化坐标或把最大化尺寸当成正常尺寸。沉浸窗口仍保存进入沉浸前的正常边界，热键和浏览器资料目录不受这些操作影响。

字幕/方向浮窗独立置顶、可拖动，正文按窗口宽度换行。浮窗可单独开关；在穿透模式中随主窗关闭输入命中，紧急恢复后恢复可调节状态。设置保存浮窗位置，主窗退出时必须关闭浮窗。

配置存于 %LOCALAPPDATA%/GuideMate/settings.json；浏览器数据存于该目录 WebView2 子目录。收藏保存标题、网址、播放秒数、倍速与可空 LocalPath，本地收藏通过磁盘路径重开文件；路径失效时提示用户。历史最多 80 条，每 12 秒及导航/退出时保存进度。同页刷新恢复播放位置和倍速，切换视频清空导入字幕。先写临时文件再替换配置，避免中断产生半文件。无效 JSON 保留原文件，下一次保存前复制为 .invalid-时间戳，再使用默认配置。正常隐藏不退出播放器，退出时保存并注销热键和托盘。

上述为未选择其他目录时的默认位置。正常启动显式传入 --data-dir 后，以 active-profile.json 在默认根目录记住绝对路径；以后的启动和发布版沿用该选择，不把临时演示目录误当新资料。已有自定义设置及浏览器资料继续原地使用，不迁移或合并 WebView2 数据。记录缺失时使用默认根目录；记录无效或选定目录缺失时停止并提示，不静默回退到空资料。--isolated 不读取/更新正式选择，未指定目录时分配新的临时目录。

WebView2 明确使用所选目录下的 WebView2 子目录作为 UserDataFolder；修改程序位置或更新程序集不改变它。发布脚本只复制二进制和资源，不覆盖用户目录；已在运行的发布程序会阻止发布，要求正常退出以保存设置。跨程序目录的持久性验证仅使用隔离资料中的合成持久 Cookie、LocalStorage 与自定义热键，不读取真实账号。保留本地资料不保证网站会话永不过期。

只保存工具运行所需状态，不记录用户全局按键，不读取游戏内存，不在后台上传屏幕或字幕。日志只包含应用异常和导航状态，不输出 cookie、登录令牌或媒体 URL 中的敏感查询参数。

## 10. 攻略视觉与实机研究阶段

历史开发使用原神攻略合集和本地 AV1 样本，个人样本不随仓库分发。已实现攻略侧图像方向识别；实机位置匹配、相机/角色分离和视觉战斗仍未实现。作者放大的小地图需要单独校准，不能直接用作实机 ROI。完整机制与历史样本结果见 [GENSHIN.md](GENSHIN.md)。

Vision 模块用固定版本 OpenCvSharp4/OpenCV 的 HSV、轮廓、多边形、凸包和尾部凹口判断玩家箭头尖端；对噪声自交检查循环索引顺序，低得分、触边、复杂轮廓或不明确的候选拒识。几何得分不解释为概率。校准窗口支持正方形框选、时间预览、北向角度及取消。只有北向固定的小地图才输出八方位，否则显示画面角度。

VideoAnalysis 使用已安装 FFmpeg/ffprobe，以 ArgumentList 传参，不经命令解释器。每秒 2 帧解码选区到 160×160 BGR 管道，保存每 0.5 秒的角度或 null；采样存在帧舍入，不是原始逐帧精度。取消或失败结束解码进程，不替换已有结果。路径、大小和修改时间绑定 JSON 缓存，存于数据目录 vision；校验版本、数值、递增时间和大小。原文件不变，不上传视频。

播放器按 currentTime 二分查找；拒识和过期清空方向，暂停冻结、跳转重算、切换视频清理。关闭视觉后回到字幕规则，浮窗标出来源。没有从攻略箭头推断用户所在位置。

箭头识别优先保留原高亮青色及精确尾凹口路径。该路径拒识后，ArrowShapeMatcher 在窄青色范围恢复较暗的轮廓，使用 12 类数学箭头形状、每 5 度旋转匹配，48×48 归一化形状通过 ulong 位图与 PopCount 计算交并比。保留面积、选区中心、触边、尾部凹口约束；最高相似度至少 0.78，且比相隔 40 度以上的候选高至少 0.02。有效凹口深度至少为轮廓包围盒对角线的 0.015，其相对质心的轴向投影须在后方超过 0.06 对角线，横向距离须小于 0.18 对角线，防止重叠图标或翼角提供虚假的尾部证据。模板延迟初始化并复用，不训练、不上传图像，不保存或修改校准，也不在无法识别时延用旧方向。模板输出角度为 5 度档位，精确路径继续输出连续角度；极低分辨率或严重压缩仍可能拒识或误判。

在线视频单独使用实时取帧，不调用离线 FFmpeg 分析。网页桥返回视频内在尺寸、播放时间和经过 object-fit/iframe 变换的显示区域；可读取时输出 canvas 帧，跨域 taint 时用 WebView2 原生预览裁剪。每 0.5 秒采样，后台检测复用 ArrowDetector。OnlineVisionCalibration 保存当前统一的 ROI 和北向参数，仅由用户确认保存新校准时更改；换网址、切集、重启与分辨率变化均复用原始相对选区。运行时将其映射到当前视频尺寸，源参数不写回。旧 OnlineVisionProfiles 表保留，首次加载优先采用最近历史匹配的有效校准，未匹配则采用最后有效条目。导航、视频切换、跳转、尺寸变化、关闭视觉、隐藏及最小化使旧识别结果失效，异步返回后再检查媒体标识和任务代次。低分辨率区域可允许较浅的尾部凹口，保留相同几何得分门槛；原离线阈值不变。窗口缩得过小、播放器被遮挡或画面不完整时拒识；不保证所有站点或受保护媒体可捕获。

下一步用对应实机样本识别普通小地图 ROI，分离相机方向与角色标记，再在已知地图内做位置和路线匹配。没有地图基准时不得输出绝对坐标。选型由样本验证决定，不预先承诺全游戏通用。

需记录误检率、无法识别率、方向角误差、处理延迟、CPU/GPU 占用。低置信度输出“无法确定”而非稳定假箭头。至少覆盖旋转镜头、暂停、低画质、缩放、战斗、室内、楼层变化和传送。视频样本测试通过不等于真实游戏验证通过。

## 11. 构建、发布与验证

软件更新由 `GitHubReleaseClient`、`ReleaseVersion`、`UpdatePackage` 和独立 WPF 项目 `GuideMate.Updater` 实现。启动开关默认开启，设置保存后生效；后台检查 `vibub/GuideMate` 最新正式 Release，以语义版本比较，并通过设置/托盘提供手动入口。弹窗显示更新说明，用户确认后启动从临时目录运行的更新器。更新器下载指定标签 ZIP，优先校验 GitHub 自动计算的 SHA256 digest；仅为旧 Release 保留同名 `.sha256` 的回退兼容，新发布不生成或上传该文件。验证解压路径及程序文件清单后，通过仅当前用户可访问的命名管道通知主程序保存并正常关闭。等待所有同目录 GuideMate 进程退出后覆盖程序文件，失败时恢复备份，不强制结束进程。只删除旧清单记录的废弃程序文件，保留设置、WebView2、vision、其他未知文件和当前资料目录。完成界面提供“启动随引”和“退出”，显式启动传入原 `--data-dir`；退出后清理本次临时文件，恢复失败时保留备份。

开发环境：.NET 10 SDK、WebView2 Runtime；NuGet 固定 WebView2、OpenCvSharp4 和 runtime.win.slim 4.13.0.20260627。OpenCV native DLL 随发布包提供；本地分析使用已有 FFmpeg/ffprobe，没有新增系统 SDK。升级后重新验证透明视频绘制与真实图像。脚本优先使用项目 .tools/dotnet/dotnet.exe，找不到时检查系统 SDK。

发布命令生成 artifacts/GuideMate-win-x64 框架依赖多文件目录，不携带 .NET 运行库。提供 Start-GuideMate.ps1 和双击入口，不把源码包描述为已安装应用。

核心自动检查必须覆盖字幕解析、时间偏移、重叠/边界、JSON 字幕、方位复合词、否定、视角与战斗事件。浏览器桥脚本做语法检查；真实客户端用样例媒体验证播放暂停、跳转、倍速、字幕同步、挖孔和透明度。至少一次使用 Windows UI 截图查看整体布局与浮窗，并检查窗口尺寸变化。

当前构建与公开回归方法见 [TESTING.md](TESTING.md)。本机历史验收和 artifacts 不随仓库或发布包提供；任何人工验收结论需要对应的环境与实际证据。

## 12. 兼容性与交付边界

优先支持窗口化和无边框全屏游戏。独占全屏、特殊输入保护、管理员级游戏、跨域 iframe、站点播放器更新可能影响覆盖或控制，必须实测后描述支持范围。不能通过降低系统安全设置或注入游戏进程解决兼容性。

最终交付包含本文、可编辑源码、启动与发布脚本、运行目录和实际验证记录。任何未实测的能力明确标记为未验证；任何未实现的 AI 研究能力不会在产品中显示为已可用。

## B 站全屏弹幕

沉浸时使用独立的原生透明置顶窗口覆盖小窗所在显示器的完整物理边界（包含任务栏区域）。窗口设置 WS_EX_NOREDIRECTIONBITMAP，内容直接由 DirectComposition 合成；WS_EX_LAYERED 的统一 alpha 为 255，配合 WS_EX_TRANSPARENT / WS_EX_NOACTIVATE、HTTRANSPARENT 和 MA_NOACTIVATE 保持跨进程点击穿透及不抢焦点。窗口没有 WPF HwndTarget，也不调用 UpdateLayeredWindow。不改主窗置顶、透明度、X 光、字幕窗及热键策略。暂停时冻结，倍速时同步；导航、播放器变化和 seeking 代次清理旧评论。隐藏、最小化、关闭开关和退出沉浸移除弹幕图层并收起覆盖层。设置仅在保存时写入 FullscreenDanmaku，旧资料缺字段默认开启，不改变既有浏览器目录。

桥接读取当前 B 站 nano 播放器的 player.danmaku.getDanmakuX().manager.visualArray。使用已通过播放器筛选、未隐藏且已显示的 textData，保留普通滚动、顶部、底部、反向文字的内容与颜色；不下载弹幕接口、不读取 Cookie、不触发发送请求。用 dmid 和 stime 去重，seeking 事件推进代次。每批最多 240 条，屏幕最多 120 条，按轨道避免重叠；不支持高级脚本或特效的原有动画。播放器未暴露该结构时不创建弹幕层。

适配依据为 2026-10-08 读取的 B 站公开播放器 nano 4.10.4（构建时间 2026-09-20）：core.js 暴露 getDanmakuX，npd.491.8e830665.js 管理 visualArray / textData / isHide / showed，npd.505.2d76eed1.js 配置弹幕筛选并将实例挂到播放器。以上内部结构可能随网站更新而改变，真实站点验收需独立于合成模型检查。

全屏弹幕仍在独立进程的 STA 线程接收快照和生成字形：WPF 只在接受新评论时将描边文字光栅化一次，Direct2D 将文字尺寸的位图上传到 DirectComposition 表面。DWM 持有每条评论的图层，执行位移及到期隐藏动画；不订阅 CompositionTarget.Rendering，也不每帧重建整屏透明绘制指令。高 DPI 长文本按 2048 像素分块，保留完整内容并避开单纹理尺寸限制。普通快照沿用系统动画，暂停、倍速或超过 0.1 秒的时钟偏差才重定位；超过 1.25 秒的跳转清理旧图层。待处理状态合并为最新快照，同屏拖动不重复传输未变化的状态。跨显示器或运行时缩放变化时，按物理边界与最新 DPI 重建图层；隐藏、退出和关闭释放资源。小窗位置更新继续按输入计时提交，不等待弹幕绘制。图形初始化或上传失败会退出弹幕进程，由主窗既有失败反馈报告，不切回整屏 WPF 绘制。发布采用不自带 .NET 的普通多文件布局，应用与图形绑定 DLL 独立存放，原生库从程序目录加载。OpenCV Slim 和外部 FFmpeg 流程保持一致。
